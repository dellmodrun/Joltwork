LIVE REPOSITORY BROWSER

Read the complete files, not decorative excerpts.

This browser loads each full file directly from the public main branch. The Rust program parses the signed intent, validates accounts, invokes policy and route programs through CPI, reloads token balances, enforces postconditions and returns a settlement receipt. The SDK builds the matching instruction format; the tests exercise its codec.

You do not need to read Rust to understand what is being proven. Start with JOLT_GUARD.md for the execution contract, then open sdk/src/index.ts to see how an application builds the instruction. The Rust file is the final authority: it shows which accounts are trusted, which values are checked and which errors stop settlement.

The browser deliberately displays the repository’s current files rather than copied snippets maintained separately for marketing. That means a reader can compare the explanation on this site with the implementation on GitHub and see when the two diverge. Tests demonstrate deterministic encoding and account assembly, but they are not a substitute for an independent security review.

REPOSITORY MAP

Every artifact has one job.

The interface formats and implementation are separated so wallets, routers, launchers and indexers can integrate only the layer they need.

Think of the repository as three layers. The specification names the promises. The SDK translates those promises into bytes and ordered accounts. The Solana program enforces them. CI then repeats the available tests whenever implementation files change. The table is a map of those layers, not a claim that every production dependency has already shipped.

RELEASE BOUNDARY

What the repository proves—and what deployment must still prove.

Source code can prove that a mechanism has been implemented and can show the assumptions its authors made. The devnet manifest now also publishes the executable Program ID, source commit and reproducible SBF hash. It still cannot prove that every route adapter passes the right accounts or that no adversarial input was missed; those claims require integration coverage and external review.

This distinction matters to users. The public devnet binary is a real test deployment, while the browser Intent Composer remains an instruction and manifest surface until its router adapter is connected. Mainnet deployment, production monitoring and audit remain separate release gates.

Inspectable now

  • Authority, expiry and route validation in Rust.
  • Classic SPL and Token-2022 balance parsing.
  • Pre-hook, route and post-hook CPI execution.
  • Checked max-input and min-output arithmetic.
  • SDK encoder and JRC1 receipt decoder.
  • Verified, executable devnet Program ID and build manifest.

Required for public mainnet use

  • Published, verified mainnet Program ID.
  • Audited router and launchpad adapters.
  • Independent security review.
  • Production RPC and transaction monitoring.
  • Versioned releases and incident process.
